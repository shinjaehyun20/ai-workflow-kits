# Agent Team Ops 가이드

Agent Team Ops는 여러 Claude Code 세션을 **살아있는 팀**으로 띄우고, 원격에서 지시·승인하며, 충돌 없이 합치는 운영 절차다.

이 패키지는 공개 가이드
[*클로드 코드(Claude Code) 멀티에이전트 팀 자동화 완성 가이드*](https://wikidocs.net/book/19736)
의 구조를 이 레포의 런타임 중립·evidence-first 형식으로 옮긴 것이다.

## 어디에 위치하는가

```text
teamwork-preview  ->  agent-team-ops  ->  keepworking
(목표 잠금·런치 패킷)   (팀 기동·운영)        (멤버별 evidence 루프)
```

- `teamwork-preview`: 큰 작업을 잠그고 위임 가능한 런치 패킷을 만든다.
- `agent-team-ops`: 그 패킷을 **여러 멤버가 동시에** 수행하도록 팀을 띄우고 운영한다.
- `keepworking`: 각 멤버가 자기 작업을 evidence 기반으로 끝까지 돈다.

## 핵심 흐름

```text
환경 구성 -> 팀 차터 -> 기동 -> 배정 -> 원격 운영 -> 병렬 실행 -> 충돌 방지 팬인 -> evidence 종료
```

| 단계 | 역할 | 결과 |
| --- | --- | --- |
| 환경 구성 | 병렬 세션 수단 + 도구 스택 + 격리 브랜치 확인 | 도구 스택 상태 |
| 팀 차터 | 멤버 역할·경계·공유 작업목록·충돌 규칙 고정 | 차터 문서 |
| 기동 | 멤버당 세션 1개, 자기 차터 조각만 전달 | 기동 상태 |
| 배정 | 런치 패킷 브랜치를 멤버에 매핑 (전체 프롬프트 텍스트) | 배정표 |
| 원격 운영 | 휴대폰에서 지시·승인, 완료 알림 수신 | 승인 로그 |
| 병렬 실행 | 멤버별 evidence-first 루프 동시 진행 | 멤버 결과 |
| 충돌 방지 팬인 | 같은 파일 동시 소유 금지, 의존 결과 재검증 | 충돌 점검표 |
| evidence 종료 | 메인 세션이 통합 결과 검증 후 종료 | 종료 결정 |

## 사용 기준

사용한다:

- 잠긴 런치 패킷이 독립 브랜치로 이미 나뉘는 경우
- 별도 컨텍스트를 가진 병렬 세션이 긴 단일 컨텍스트보다 유리한 경우
- 휴대폰 등에서 원격으로 지시·승인하고 싶은 경우
- 토큰 효율적인 공유 도구 스택을 모든 멤버에 깔고 싶은 경우

사용하지 않는다:

- 단일 파일 수정, 단순 편집 등 한 루프로 끝나는 일
- 팀 기동 오버헤드가 병렬 이득보다 큰 일
- 수락 게이트를 우회하려는 목적 (멤버 완료는 최종 수락이 아니다)

## 역할 모델 (Triple Crown 분업)

가이드 7장의 Triple Crown 전략을 역할 파이프라인으로 일반화한다. 특정 도구
이름이 아니라 "어떤 질문에 답하는 슬롯인가"로 본다.

| 역할 | 답하는 질문 | 스택 슬롯 | 가이드의 예시 도구 |
| --- | --- | --- | --- |
| 전략 / 검증 | 무엇을, 왜 | 전략·검증 도구 | gstack |
| 구조 / 실행 | 어떤 순서로 | 프로젝트·스펙 실행 도구 | GSD |
| 품질 / 방법 | 어떻게 잘 | 스킬·방법론 도구 | superpowers |
| 토큰 최적화 | 어떻게 예산 안에서 | 출력 압축 프록시 | RTK |

모든 멤버가 같은 파이프라인을 상속하므로 팬인 시점에 결과가 비교 가능하다.

설치·실행 단계는 `tooling-setup.md`를 본다.

## 충돌 방지 규칙 (8장)

병렬 멤버가 가장 자주 깨지는 지점이다. 메인 세션이 강제한다.

- **파일 단일 소유**: 한 파일은 한 멤버만 수정한다. 겹치면 직렬화한다.
- **워크트리 격리**: 멤버마다 별도 브랜치/워크트리에서 작업한다.
- **공유 계약 단일 변경**: 스키마·인터페이스는 차터가 지정한 한 멤버만 바꾼다.
- **의존 재검증**: 의존 작업은 상위 결과가 확정된 뒤 그 결과 기준으로 재검증한다.
- 병합 전 충돌 점검표를 통과하지 못하면 합치지 않는다.

## 원격 운영과 승인 게이트 (4~5장)

휴대폰 Claude 앱으로 PC의 팀에 접속해 지시를 보내고 도구 호출을 승인할 수 있다.
완료는 푸시 알림으로 감지한다. 다만:

- **승인 게이트는 채널로 완화되지 않는다.** 원격 탭도 파괴적·외부 노출 동작이면
  로컬과 동일한 확인을 받는다.
- 완료 알림은 "멤버가 막혔거나 끝났다"를 알리는 신호일 뿐, 검증을 건너뛰는
  근거가 아니다. 메인 세션이 항상 검증 후 수락한다.

## 고급 운용 (8장)

- **GitHub Actions 자동화**: 팀 산출물을 CI에 연결해 멤버 결과를 자동 검증한다.
  이 레포에서는 PR 활동 이벤트 구독으로 CI·리뷰 신호를 받아 후속 수리를 돌릴 수
  있다.
- **컨텍스트 관리**: 멤버별 컨텍스트를 분리하고, 토큰 최적화 프록시로 도구 출력을
  압축해 장시간 세션을 유지한다.
- **충돌 방지**: 위 규칙을 차터에 명시하고 팬인마다 점검한다.

## 완료 기준

Agent Team Ops의 완료는 "팀을 띄웠다"가 아니라 다음을 갖춘 종료다.

- 팀 차터와 멤버별 역할 배정
- 도구 스택 상태 (무엇이 실제 설치·활성인지)
- 원격·파괴적 동작에 대한 승인 상태
- 멤버별 브랜치/워크트리 상태
- 병합 전 충돌 점검 결과
- evidence 경로와 미해결 리스크
- 메인 세션의 종료 결정

## 안티패턴

| 안티패턴 | 이유 |
| --- | --- |
| 한 루프로 끝날 일에 팀 기동 | 병렬 이득 없이 오버헤드만 |
| 같은 파일 병렬 소유 | 경쟁 상태와 병합 노이즈 |
| 원격 승인으로 게이트 우회 | 폰 탭도 파괴적 동작이다 |
| 완료 알림을 수락으로 간주 | 완료에는 검증된 evidence가 필요 |
| 멤버의 자유로운 범위 확장 | 차터 드리프트로 팬인 비교 불가 |
| 미검증 도구를 스택에 포함 | "설치됨"은 확인되어야 한다 |
