# Keepworking 한글 가이드

Keepworking은 AI가 한 번 답하고 멈추는 문제를 줄이기 위한 실행 루프입니다.

핵심은 단순합니다.

```text
목표 고정 -> 계획 -> 실행 -> 검증 -> 보수 -> 재검증 -> 종료
```

## 장점

- 답변이 아니라 증거를 기준으로 종료합니다.
- 작업 난이도에 따라 `simple`, `medium`, `complex`로 나눕니다.
- 검색, 분류, 검수처럼 독립적인 작업은 병렬로 처리할 수 있습니다.
- 검증이 실패하면 같은 검증을 다시 통과할 때까지 보수 루프로 들어갑니다.
- Codex, Claude Code, Gemini, GitHub Copilot처럼 서로 다른 AI 도구에 같은 운영 원칙을 옮길 수 있습니다.

## Goal 스킬과의 비교

| 구분 | Goal 스킬 | Keepworking |
| --- | --- | --- |
| 핵심 역할 | 목표와 종료 조건을 고정 | 목표 달성까지 실행 루프를 계속 진행 |
| 주로 하는 일 | 무엇을 끝낼지 정의 | 어떻게 파고들고 검증할지 운영 |
| 산출물 | 목표, 상태, 종료 조건 | 작업 결과, 증거, 검증 결과, 남은 위험 |
| 실패 대응 | 목표가 막혔는지 표시 | 보수 대상을 좁히고 재검증 |
| 관계 | 시작점 | 실행 엔진 |

두 개는 경쟁 관계가 아닙니다.

Goal은 큰 종료 조건을 고정하고, Keepworking은 그 목표 아래의 현재 실행 단위(action unit)를 닫습니다. action unit은 "무엇을, 어디까지, 어떤 증거로 끝났다고 볼지"를 작게 고정한 단위입니다.

좋은 조합은 다음과 같습니다.

```text
Goal 스킬로 목표와 종료 조건을 고정
-> Keepworking으로 실행, 검증, 보수, 재검증
-> 증거가 있을 때 종료
```

## Action unit 종료조건

큰 목표를 바로 완료 처리하지 말고, 현재 행위를 먼저 닫습니다.

```text
행위: inspect/edit/create/run/compare/verify/repair/publish
대상: 파일, 산출물, 이슈, 데이터셋, 배포, 의사결정, 브랜치
범위: 이번 slice에 포함되는 것과 제외되는 것
소유자: main chat, worker, 도구, 외부 앱, 사용자
완료조건: 관찰 가능한 done 조건
검증자: 테스트, 빌드, 로그, 렌더, diff, 원천 확인, 리뷰 통과, 사용자 확인
```

검증자가 없으면 `done`이 아니라 `partial`, `blocked`, `failed`처럼 남겨야 합니다.

## 반복 성공과 실패

반복 성공은 playbook 또는 skill 후보가 됩니다. 단, 재사용 조건과 검증자가 분명해야 합니다.

반복 실패는 stop rule로 남깁니다. 같은 입력에 같은 방법을 다시 쓰지 말고, 원천, 소유자, 도구, 모델/추론 단계, 검증자, 범위 중 하나 이상을 바꿔야 합니다.

## AI별 적용 변이

| AI | 적용 방식 | 핵심 차이 |
| --- | --- | --- |
| Codex | `SKILL.md`와 `AGENTS.md` 중심 | 실제 파일 수정, 검사 실행, 증거 확인에 강함 |
| Claude Code | `simple`, `medium`, `complex` agent 중심 | 작업 난이도별 worker 분리가 자연스러움 |
| Gemini | system prompt 중심 | 문맥 정리, 비교, 종합 설명에 적합 |
| GitHub Copilot | repository instruction과 prompt 중심 | 코드 저장소 안에서 구현/검수 지침으로 쓰기 좋음 |

## 언제 쓰나

- 원인을 찾을 때까지 계속 디버깅해야 할 때
- 검증 실패 후 보수와 재검증이 필요한 때
- 여러 파일이나 문서를 나눠서 확인해야 할 때
- 작업 완료 주장을 증거로 닫고 싶을 때
- 여러 AI 도구에 같은 운영 방식을 적용하고 싶을 때

## 완료 보고 형식

```text
현재 목표:
선택한 티어:
현재 action unit:
완료조건:
진행한 작업:
증거:
검증:
재사용 패턴:
stop rule:
남은 위험:
다음 액션:
종료 판단:
```

종료 판단은 반드시 증거와 함께 작성합니다.
