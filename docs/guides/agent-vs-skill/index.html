에이전트vs스킬

세 도구로 보는 Agent와 Skill의 차이 — 채용한 전문 일꾼인가, 펴 보는 작업 매뉴얼인가. 쉬운 비유부터 실제 코드 샘플까지.

01SUMMARY · 한 줄 요약

한 문장이면 에이전트는 '일꾼',
스킬은 '매뉴얼'입니다.

같은 자동화 도구지만 역할이 다릅니다. 일꾼을 부를지, 매뉴얼을 펼칠지.

Agent · 에이전트

전문 일꾼 (페르소나)

자체 컨텍스트·도구·권한·판단을 갖고 위임받은 작업을 끝까지 수행하는 재사용 일꾼 정의.

  • 자기만의 작업 책상(별도 컨텍스트)을 새로 차림
  • 스스로 판단하고 일감 전체를 처리
  • 끝나면 요약만 메인 대화에 돌려줌
Skill · 스킬

작업 매뉴얼 (플레이북)

특정 작업 수행법을 instructions·스크립트·리소스로 묶은 SKILL.md 폴더. 필요할 때만 펼쳐짐.

  • 평소엔 책장에 꽂혀 자리(컨텍스트)를 거의 안 차지
  • description이 요청과 맞을 때만 본문 로드
  • 일꾼을 전문가로 임시 변신시키는 문서
02ANALOGY · 사무실 풍경

전문가를 채용할까,
매뉴얼을 펼칠까

에이전트와 스킬을 회사에 비유하면 이렇습니다.

에이전트 = 채용한 전문가독립된 자리에서 일을 통째로 맡아 끝낸다
스킬 = 책장 속 매뉴얼관련 작업을 만났을 때만 꺼내 읽는다
03COMPARISON · 비교표

8가지 축으로 본 차이

같은 질문에 둘이 어떻게 갈라지는지 한눈에.

축에이전트 (Agent)스킬 (Skill)
정의별도 컨텍스트·프롬프트·도구·권한을 가진 전문 일꾼. 위임받아 처리 후 요약 반환작업 수행법+선택 스크립트·참조파일을 묶은 SKILL.md 폴더. 일반 에이전트를 임시 전문가로
핵심 목적역할/페르소나 분리 — 별도 맥락에서 독립 수행, 메인 비오염능력/지식 주입 — 컨텍스트를 안 부풀리고 필요 시만 절차 로드
자율성높음 — 스스로 판단, 일감 전체를 끝까지낮음 — 호출 주체의 판단 안에서 절차·지식 제공
호출 방식자동(description 매칭) + 명시(이름·@-mention·세션 채택)자동(description 매칭) + 명시(/skill명·$skill명)
재사용 단위Markdown(+YAML) 정의 파일 1개 = 일꾼 하나SKILL.md 1개 + 번들 폴더 = 작업 패키지 하나
컨텍스트 비용별도 컨텍스트 윈도우 새로 소비. 요약만 합류점진적 공개 — 메타데이터만 상시, 본문/번들은 필요 시
대표 위치.claude/agents/ · .github/agents/ · AGENTS.mdSKILL.md (.claude/skills/ · .github/skills/ · configured Codex skill root)
대표 예시code-reviewer 서브에이전트, test-specialistpdf-processing, github-actions-failure-debugging

Cl

Claude / Claude Code

두 개념의 본가

Agent와 Skill이 가장 명확히 분리됨. Agent Skills 오픈 표준의 출발점.

Agent → Subagent

자체 컨텍스트·시스템 프롬프트·도구·권한을 가진 서브에이전트. 위임 후 요약만 반환.

위치 .claude/agents/ · ~/.claude/agents/ (재귀 스캔, 정체성=name)

호출 자동(description) + @agent-name · claude --agent

Skill → Agent Skill

SKILL.md 폴더 + 점진적 공개(메타 → 본문 → 번들). 매칭 시 온디맨드 로드.

위치 ~/.claude/skills/<name>/ (우선순위 enterprise > personal > project)

호출 자동 + /skill명, disable-model-invocation로 주체 제한

~/.claude/agents/code-reviewer.md 
---
name: code-reviewer
description: Expert code review specialist. Proactively reviews
  code for quality, security, maintainability. Use after writing code.
tools: Read, Grep, Glob, Bash
model: inherit
---
You are a senior code reviewer. Run git diff, focus on modified files,
review immediately. Organize: Critical / Warnings / Suggestions.
~/.claude/skills/pdf-processing/SKILL.md 
---
name: pdf-processing
description: Extract text and tables from PDFs, fill forms. Use
  when the user mentions PDFs, forms, or document extraction.
---
# PDF Processing
import pdfplumber
with pdfplumber.open("doc.pdf") as pdf:
    text = pdf.pages[0].extract_text()
For advanced form filling, see FORMS.md   # L3 번들 = 참조 시 로드
함께: 서브에이전트 frontmatter skills로 시작 시 스킬 프리로드 · 스킬 context: fork로 격리 서브에이전트에서 실행 → 페르소나에 능력을 얹음.

Skill → Agent Skills + Skillset

Agent Skills(SKILL.md): Anthropic 오픈 표준 채택 — Claude 스킬의 직접 대응물.

위치 .github/skills/<name>/SKILL.md (.claude/skills/도 탐지)

Skillset(별개): GitHub App의 최대 5개 API 엔드포인트. SKILL.md 아님!

---

Agent → AGENTS.md

스키마·frontmatter 없는 순수 Markdown 지침("README for agents").

위치 레포 루트 + 전역 ~/.codex/AGENTS.md (git 루트→cwd, 가까운 파일이 override)

호출 자동·실행당 1회. 페르소나 아님 — 여러 에이전트가 공유

호출 자동 + 명시(/skills·$skill명). 선행 Custom Prompts는 deprecated

05TOGETHER · 함께 쓰기

일꾼 + 매뉴얼

둘은 경쟁이 아니라 보완 관계. 에이전트가 스킬을 펼쳐 읽습니다.

예: Claude 서브에이전트는 skills 필드로 시작 시 스킬을 프리로드하고, 반대로 스킬은 context: fork로 격리 서브에이전트에서 실행됩니다. 전문 페르소나(에이전트)에 재사용 능력(스킬)을 얹는 구조.

06DECISION · 언제 무엇을

일꾼을 부를까, 매뉴얼을 펼칠까

에이전트를 쓸 때
  • 반복되는 한 '역할'(코드 리뷰어·테스트 전문가·보안 감사자)을 분리된 맥락에서 통째로 맡길 때
  • 작업이 길거나 메인 컨텍스트를 오염시키면 안 될 때
  • 권한/도구 세트를 격리하고 싶을 때
  • 멀티에이전트 오케스트레이션(코디네이터가 하위 일꾼 분기)
스킬을 쓸 때
  • 특정 작업 절차·도메인 지식(PDF 추출·HWPX 생성·CI 디버깅)을 여러 곳에서 재사용할 때
  • 평소엔 컨텍스트를 안 차지하게 하고 싶을 때
  • 새 페르소나가 아니라 기존 어시스턴트에 "이 작업은 이렇게"를 주입할 때
  • 스크립트·템플릿·참조문서를 번들로 묶어 배포할 때
⚠️ 일부 세부(버전 게이팅 숫자·경로·토큰 수치·GA 시점)는 도구 버전·시점에 따라 달라질 수 있습니다. 본 자료는 2026-06-15 공식 문서 기준으로 작성·교차검증되었으며, 최신 값은 각 공식 문서에서 확인하세요.
