검정 배경에 빨간 AGENT, 노란 SKILL이 대조를 이루는 타이틀 슬라이드. 하단에 "에이전트 = 일꾼 / 스킬 = 매뉴얼" 레이블 두 개.

안녕하세요. 오늘은 Claude, GitHub Copilot, OpenAI Codex, 세 가지 AI 도구에서 "에이전트"와 "스킬"이 각각 어떤 의미인지, 그리고 어떻게 다른지를 함께 살펴보겠습니다.

한쪽은 빨간색 AGENT, 다른 쪽은 노란색 SKILL. 색깔부터 다릅니다. 지금 이 두 단어, 헷갈리셨던 분들 분명 있으실 텐데요. 오늘 끝나면 깔끔하게 정리될 겁니다.

## S2. 한 줄 요약

**[화면 큐]**
흰 배경. 왼쪽 검정 패널에 "에이전트 = 전문 일꾼", 오른쪽 검정 패널에 "스킬 = 작업 매뉴얼"이 각각 설명과 함께 표시된다.

**[나레이션]**
먼저 핵심부터 딱 한 줄씩 정리해 드립니다.

에이전트는 "전문 일꾼"입니다. 자체 컨텍스트와 도구, 권한을 갖고 위임받은 작업을 처리하고, 완료 보고만 메인 대화로 가져오는 재사용 가능한 AI 페르소나 정의예요.

스킬은 "작업 매뉴얼"입니다. 특정 작업을 어떻게 수행할지 설명한 SKILL.md 파일이 핵심이고요, 관련 요청이 들어올 때만 내용이 로드됩니다. 평소엔 거의 자리를 차지하지 않아요.

일꾼이냐, 매뉴얼이냐. 이 구분이 오늘 발표의 핵심입니다.

## S3. 비유

**[화면 큐]**
검정 배경. 왼쪽 다크 레드 패널에 "채용한 전문가", 오른쪽 다크 옐로우 패널에 "책장의 매뉴얼". 각 패널에 장단점 설명이 나열된다.

**[나레이션]**
조금 더 직관적인 비유로 설명해 볼게요. 여러분이 사무실을 운영한다고 상상해 보세요.

에이전트는 "채용한 전문가"입니다. 이 전문가는 자기만의 책상이 있고, 필요한 도구도 다 갖춰져 있어요. 일감을 통째로 맡기면 알아서 처리하고 완료 보고만 가져옵니다. 중간 과정이 메인 사무실을 어지럽히지 않죠.

스킬은 "책장의 매뉴얼"입니다. 평소엔 책장에 꽂혀서 자리를 거의 차지하지 않아요. 그런데 관련 작업이 생기면 그때서야 꺼내서 읽고, 작업이 끝나면 다시 꽂아둡니다. 필요할 때만 꺼내 쓰는 전문 플레이북이에요.

에이전트는 '사람', 스킬은 '문서'. 이렇게 기억하시면 됩니다.

## S4. 비교표 8축

**[화면 큐]**
흰 배경. 8행 3열 비교표. 왼쪽 첫 열은 비교 축, 가운데가 에이전트(빨간 헤더), 오른쪽이 스킬(진한 노란 헤더).

**[나레이션]**
이번에는 8가지 축으로 좀 더 꼼꼼하게 비교해 봅니다.

정의를 보면, 에이전트는 별도 컨텍스트와 도구, 권한을 가진 전문 일꾼 정의이고, 스킬은 작업 수행법과 리소스를 묶은 SKILL.md 폴더입니다.

핵심 목적은 다릅니다. 에이전트는 "역할과 페르소나를 분리"하는 것이 목적이고, 스킬은 "능력과 지식을 주입"하되 컨텍스트를 최소화하는 게 목적이에요.

자율성도 달라요. 에이전트는 스스로 판단하고 일감 전체를 끝까지 처리합니다. 스킬은 호출 주체의 판단 안에서 절차와 지식만 제공하고, 직접 일꾼을 부리지는 않아요.

나머지 축들도 표에서 확인하실 수 있습니다. 재사용 단위, 컨텍스트 비용, 대표 파일 위치까지 비교해 두었습니다.

## S5. Claude / Claude Code

**[화면 큐]**
검정 배경. 왼쪽 어두운 레드 패널에 "AGENT — Subagent", 오른쪽 어두운 옐로우 패널에 "SKILL — Agent Skills". 각 패널에 공식 스펙이 나열된다.

**[나레이션]**
Claude와 Claude Code부터 보겠습니다.

에이전트 쪽은 "Custom Subagents"가 공식 명칭입니다. `.claude/agents/` 폴더에 YAML frontmatter와 시스템 프롬프트를 담은 Markdown 파일을 만들면 됩니다. 하위 폴더까지 재귀 스캔이 되고요, description이 요청과 맞으면 자동으로 위임이 됩니다. `@agent-이름`으로 직접 지목할 수도 있어요.

스킬 쪽은 "Agent Skills"가 공식 명칭입니다. 중요한 포인트가 있는데요, SKILL.md 오픈 표준의 본가가 바로 Anthropic입니다. 2025년 12월 18일에 공개하고 오픈소스화했어요. Claude Code·Claude API·claude.ai가 공통으로 쓰는 표준이고, 점진적 공개 방식으로 동작합니다. 항상 상주하는 메타데이터에서 시작해서, 트리거가 되면 본문이 로드되고, 참조할 때 번들 파일까지 불러오는 식이에요.

그리고 서브에이전트가 frontmatter의 `skills` 필드로 특정 스킬을 미리 로드할 수도 있습니다. 에이전트와 스킬이 함께 동작하는 방식이죠.

## S6. GitHub Copilot

**[화면 큐]**
흰 배경. 상단에 빨간 경고 배너: "⚠ Copilot에서 'agent'는 과부하 용어". 왼쪽 검정 패널에 "AGENT — Custom agents", 오른쪽에 "SKILL — 2가지 구분 필수".

**[나레이션]**
GitHub Copilot은 주의할 점이 하나 있습니다. "agent"라는 단어가 여러 의미로 쓰이는 과부하 용어입니다. Copilot coding agent라든가, Extension 타입으로서의 agent, 대화형 agent mode까지 다 다른 개념이에요.

이 발표에서 우리가 말하는 "재사용 에이전트 정의"는 Custom agents, 즉 `.agent.md` 파일입니다. `.github/agents/` 폴더에 두면 되고요, 본문 최대 3만 자. 이전에 `.chatmode.md`로 불리던 것이 `.agent.md`로 개명·마이그레이션된 겁니다. 호출 방식은 Claude와 달리 명시 선택 중심이에요.

스킬은 Copilot에서 두 가지를 구분해야 합니다. 첫째는 Agent Skills, 즉 SKILL.md 파일입니다. Claude, Codex와 같은 오픈 표준을 그대로 씁니다. 둘째는 Skillset인데요, 이건 완전히 다른 개념입니다. GitHub App에 정의하는 최대 5개의 API 엔드포인트 모음이에요. SKILL.md 파일이 아닙니다. 이 둘을 혼동하면 안 됩니다.

## S7. OpenAI Codex

**[화면 큐]**
검정 배경. 왼쪽에 "AGENT — AGENTS.md", 오른쪽에 "SKILL — Agent Skills". 별표(★)로 중요 교정사항이 강조됩니다.

**[나레이션]**
OpenAI Codex를 보겠습니다.

에이전트에 해당하는 것은 AGENTS.md 파일입니다. 그런데 중요한 특징이 있어요. AGENTS.md는 Claude의 서브에이전트처럼 특정 페르소나를 정의하는 파일이 아닙니다. 빌드 명령, 테스트 방법, 코드 스타일, 가드레일 같은 프로젝트 지침을 담은 파일이에요. Claude뿐 아니라 Cursor, Copilot, Jules 같은 여러 AI가 함께 읽는 공유 지침입니다. "에이전트를 위한 README"라고 생각하시면 됩니다.

스킬은 SKILL.md 기반 Agent Skills를 씁니다. 여기서도 중요한 교정사항이 있는데요, SKILL.md 오픈 표준을 만든 건 OpenAI가 아닙니다. Anthropic이 2025년 12월 18일에 공개한 것을 Codex가 채택한 겁니다. 그리고 Codex에서 Custom Prompts라는 선행 기능은 이미 deprecated 됐고, Skills로 완전히 대체됐습니다.

## S8. 함께 쓰기

**[화면 큐]**
흰 배경. 상단에 5개의 박스가 화살표로 연결된 흐름도: 메인 에이전트 → 서브에이전트 → SKILL.md 로드 → 작업 수행 후 요약 반환 → 메인 응답 완성.

**[나레이션]**
에이전트와 스킬은 서로 경쟁하지 않습니다. 협업합니다.

흐름을 보시면, 메인 에이전트가 특정 작업을 서브에이전트에게 위임합니다. 서브에이전트는 자기가 가진, 혹은 프리로드된 스킬의 SKILL.md를 꺼내서 읽고, 그 절차대로 작업을 수행한 뒤 요약만 메인으로 돌려보냅니다. 메인은 그 결과물로 최종 응답을 완성하죠.

Claude에서는 서브에이전트 정의 파일의 `skills` 필드에 스킬 이름을 써두면 시작할 때 자동으로 해당 스킬을 프리로드할 수 있습니다. 반대로 스킬 안에서 `context: fork`를 쓰면 격리된 서브에이전트 환경 안에서 실행하는 것도 가능해요.

전문 페르소나, 즉 에이전트에 재사용 작업 능력인 스킬을 얹는 구조. 일꾼이 자기 책상에서 매뉴얼을 꺼내 읽고 일하는 모습이라고 생각하시면 됩니다.

## S9. 언제 무엇을

**[화면 큐]**
검정 배경. 왼쪽 레드 패널에 "에이전트를 쓸 때", 오른쪽 옐로우 패널에 "스킬을 쓸 때". 각각 체크 표시와 함께 사용 케이스가 나열된다.

**[나레이션]**
그렇다면 실제로 언제 에이전트를 쓰고, 언제 스킬을 쓸까요?

에이전트는 이런 상황에 씁니다. 반복되는 한 가지 역할, 예를 들어 코드 리뷰어나 테스트 전문가, 보안 감사자처럼 특정 책임을 가진 역할을 메인 대화와 분리해서 실행하고 싶을 때요. 작업이 길거나 메인 컨텍스트를 오염시키면 안 될 때, 권한과 도구를 격리하고 싶을 때, 그리고 여러 에이전트를 오케스트레이션할 때 씁니다.

스킬은 이런 상황에 씁니다. PDF 추출이나 HWPX 생성, GitHub Actions 진단처럼 특정 작업 절차나 도메인 지식을 여러 곳에서 재사용하고 싶은데, 평소엔 컨텍스트를 차지하지 않게 하고 싶을 때요. 새로운 페르소나가 아니라 기존 어시스턴트에 "이 작업은 이렇게 해"라고 가르치고 싶을 때, 그리고 스크립트나 템플릿을 번들로 배포하고 싶을 때 씁니다.

## S10. 출처 + 주의사항

**[화면 큐]**
흰 배경. 상단 경고 배너 아래, Claude / Copilot / Codex / 오픈 표준 4개 섹션으로 공식 출처 URL이 나열된다.

**[나레이션]**
마지막으로 오늘 발표의 모든 사실은 여기 보이는 공식 문서를 기반으로 합니다.

한 가지 꼭 말씀드리고 싶은 게 있는데요, 이 세 도구는 빠르게 발전하고 있습니다. 버전에 따라 필드 이름이 바뀌거나, 경로가 달라지거나, 기능이 추가·변경될 수 있어요. 오늘 나레이션과 슬라이드의 사실은 공식 문서 기반이지만, 사용 전에는 각 도구의 최신 문서를 한 번 더 확인하시는 것을 권장드립니다.

그리고 SKILL.md 오픈 표준, agentskills.io는 Anthropic이 2025년 12월 18일에 공개한 것입니다. Claude, Copilot, Codex가 모두 이 표준을 채택하고 있다는 점, 기억해 두시면 좋겠습니다.

오늘 발표를 들어 주셔서 감사합니다. 에이전트는 일꾼, 스킬은 매뉴얼. 이 한 줄만 기억하고 가셔도 충분합니다.
