# Session → Skill 자동 변환기

현재 세션의 내용을 분석해 재사용 가능한 스킬로 변환하고 즉시 등록 가능한 `.skill` 파일로 패키징한다.

---

## Step 1: 세션 분석

대화 히스토리 전체를 검토하고 아래 항목을 추출한다. **추측하지 말 것. 대화에서 명확히 확인된 것만 추출.**

### 1-1. 사용된 도구 & 순서
- 어떤 tool이 몇 번, 어떤 순서로 호출됐는가?
- 반복적으로 사용된 도구 패턴이 있는가?

### 1-2. 트리거 패턴
- 사용자가 어떤 말/문맥에서 이 작업을 시작했는가?
- 유사 트리거 표현을 3~5개 도출한다.

### 1-3. 산출물 형식
- 최종 결과물은 무엇인가? (파일 타입, 구조, 포맷)
- 중간 산출물이 있는가?

### 1-4. 반복 수정 패턴 / 엣지케이스
- 사용자가 수정을 요청한 지점은 어디인가?
- 예외 처리가 필요한 케이스가 있었는가?

---

## Step 2: 사용자 확인

분석 결과를 아래 형식으로 제시하고 사용자 승인을 받는다.

```
## 세션 분석 결과

**스킬 이름 (제안)**: [slug-form-name]
**한 줄 설명**: [무엇을 하는 스킬인가]

**트리거 표현**:
- "..."
- "..."

**핵심 워크플로우**:
1. [단계 1]
2. [단계 2]
...

**산출물**: [파일/형식]

**엣지케이스**: [있으면 명시, 없으면 "없음"]

---
이 내용으로 SKILL.md를 작성할까요? 수정이 필요하면 알려주세요.
```

사용자가 승인하면 Step 3으로 진행. 수정 요청이 있으면 반영 후 재확인.

---

## Step 3: SKILL.md 작성

`<work-dir>/<skill-name>/SKILL.md` 경로에 생성.

### SKILL.md 필수 구조

```markdown
---
name: <skill-name>
description: |
  [무엇을 하는가] + [언제 트리거되는가 — 구체적 표현 포함]
  트리거 표현: "...", "...", "..." 등의 입력 시 반드시 이 스킬을 사용할 것.
---

# [스킬 제목]

[한 줄 목적 설명]

---

## 워크플로우

### Step 1: [단계명]
[상세 지침]

### Step 2: [단계명]
[상세 지침]

...

## 주의사항 / 엣지케이스
- [항목]
```

### 작성 원칙
- description은 "언제 써야 하는가"를 명확히 포함할 것 (undertrigger 방지)
- 각 Step은 Claude가 그대로 실행할 수 있도록 구체적으로 작성
- 추측 기반 단계 금지 — 세션에서 확인된 패턴만 포함
- 필요 시 `references/` 또는 `scripts/` 서브디렉터리 추가 가능

---

## Step 4: 저장 및 전달

### 4-1. /mnt/skills/user/ 에 직접 저장

작업 디렉터리(`<work-dir>/<skill-name>/`)에서 완성된 스킬을 유저 스킬 폴더로 복사한다.

```bash
# 유저 스킬 폴더에 디렉터리 생성 후 복사
cp -r <work-dir>/<skill-name> /mnt/skills/user/<skill-name>
```

> ⚠️ `/mnt/skills/user/` 는 read-only일 수 있음. 쓰기 실패 시 아래 .skill 패키징으로 fallback.

### 4-2. (Fallback) .skill 패키징 후 present_files

`/mnt/skills/user/` 직접 쓰기가 불가한 경우:

```bash
cd <work-dir>
zip -r <skill-name>.skill <skill-name>/
cp <skill-name>.skill /mnt/user-data/outputs/
```

`present_files` 도구로 `/mnt/user-data/outputs/<skill-name>.skill` 전달.

### 4-3. 완료 메시지 형식

직접 저장 성공 시:
```
✅ 스킬 등록 완료

**위치**: /mnt/skills/user/<skill-name>/SKILL.md
**즉시 사용 가능**: 다음 대화부터 트리거 표현으로 자동 로딩됩니다.

테스트 트리거 예시:
- "..."
- "..."
```

Fallback(.skill 파일) 시:
```
✅ 스킬 패키징 완료

**파일명**: <skill-name>.skill
**설치 방법**: Claude.ai Settings > Skills > Install from file

테스트 트리거 예시:
- "..."
- "..."
```

## 환경별 주의사항

| 환경 | 비고 |
|------|------|
| Claude.ai 대화창 | `present_files` 사용 가능. 서브에이전트 없음 — 순차 실행 |
| Cowork dispatch | 서브에이전트 사용 가능. `present_files` 확인 후 사용 |

---

## 실패 케이스 처리

- **세션 내용 불충분**: "이 세션만으로는 스킬 패턴을 추출하기 어렵습니다. 어떤 작업을 스킬로 만들고 싶으신지 구체적으로 말씀해 주세요."
- **이름 충돌 가능성**: 기존 스킬과 유사한 이름이면 사용자에게 알리고 새 이름 제안
- **산출물 불명확**: 사용자에게 "최종 결과물 형식이 무엇인가요?" 질문 후 진행

```
환경 무관하게 동작. 산출물은 present_files로 전달.
저장 위치: /mnt/user-data/outputs/
```

## ✅ 실행 검증 (필수)

```
완료 후:
1. SKILL.md 트리거 표현 최소 5개 이상 확인
2. 실행 순서 단계별로 명확히 구분됐는지 확인
3. Anti-rationalization 블록 포함됐는지 확인
4. Verification 블록 포함됐는지 확인
5. .skill 파일 패키징 확인
```

---

## ❌ Anti-rationalization

| 스킵 시도 | 반박 |
|----------|------|
| "대화 내용 그대로 복사해서 스킬 만들어도 돼" | 대화체는 스킬로 작동 안 함. 반드시 워크플로우 형식으로 재구조화 |
| "트리거 표현 2~3개면 충분해" | 트리거 부족하면 스킬이 활성화 안 됨 |
| "사용자 확인 없이 바로 저장해도 돼" | 스킬 내용 검증 없이 저장하면 잘못된 스킬이 자동 실행됨 |
