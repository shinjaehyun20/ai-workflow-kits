Step 01

문제:
기록이 흩어진다

Claude는 Claude 대화창에, Codex는 작업 디렉터리에, Gemini는 별도 문서에 기록을 남긴다. 도구를 바꿀 때마다 "오늘 내가 뭘 했지?"를 다시 찾아야 한다.

핵심 고통: 같은 날, 같은 프로젝트인데 AI 도구마다 기록 위치가 달라 히스토리가 단편화된다.

Cp

같은 날인데 4군데 흩어진 기록

Step 02

트리거:
"기록해줘" 한 줄

대화를 마치고 "log it" 또는 "기록해줘"라고 입력한다. AI 도구가 현재 대화에서 핵심을 추출해 오늘 일지에 구조화된 항목을 추가한다.

설계 원칙: 기록 명령은 자연어 한 줄. 타임스탬프·섹션·포맷은 LOG_CONTRACT가 결정한다.
API 응답 캐싱 레이어 설계 완료
→ "기록해줘"
Claude · daily-log 오늘 일지에 추가할게요.
완료 /logs/2025/06/2025-06-22-daily.md
→ Claude 섹션 14:32 항목 append ✓

Step 03

환경 감지:
오늘 일지 경로 보장

런타임은 먼저 볼트 루트와 날짜를 감지해 오늘 일지 파일 경로를 확정한다. 파일 존재 여부에 따라 분기한다.

분기 원칙: 파일이 없으면 헤더 + 섹션 골격으로 신규 생성. 파일이 이미 있으면 내 섹션에 시간슬롯만 append — 다른 섹션·기존 내용은 절대 건드리지 않는다.
vault root <vault> ✓
today YYYY-MM-DD ✓
target path <vault>/logs/YYYY/MM/YYYY-MM-DD-daily.md ✓
파일 없음 (absent)
헤더 + 섹션 골격
신규 생성 → 내 섹션 첫 항목 append
파일 있음 (present)
기존 파일 열기
내 섹션 끝에만 시간슬롯 append
다른 섹션 불변

Step 04

Append-only:
내 섹션에만 추가

AI는 자기 섹션(예: ## Claude) 끝에만 새 항목을 추가한다. 다른 섹션을 읽지도, 수정하지도 않는다. 기존 내용은 절대 건드리지 않는다.

불변 규칙: 자기 섹션 append만. 다른 AI 섹션 read/write 금지.

Step 05

멀티AI 공유:
같은 파일, 각자 섹션

Step 06

LOG_CONTRACT:
충돌을 0으로

LOG_CONTRACT는 섹션 소유권·append-only 규칙·환경 감지 절차를 명문화한 계약이다. 모든 AI 런타임이 이 계약을 따르기 때문에 동시에 기록해도 충돌이 없다.

핵심 보장: 어떤 AI가 먼저 열어도, 어떤 순서로 써도 — 다른 AI의 내용을 덮어쓰지 않는다.

자기 섹션 끝에
append만

✕ 금지

다른 섹션
read / write

✓ 허용

파일 없으면
자동 생성

✕ 금지

기존 내용
수정·삭제

✓ 필수

모든 항목에 HH:MM 타임스탬프 — 시간 없는 항목은 규약 위반

0 충돌 — 동시 기록해도 안전

Step 07

하나의 일지, 전체 히스토리

장점: 1개 파일 = 전체 맥락. 어떤 AI가 언제 무엇을 했는지 한눈에.

#핵심 정리

왜 Multi-AI Daily Log인가

01 · 트리거

"기록해줘" 한 마디

대화가 끝날 때 자연어 한 줄로 기록을 요청한다. 포맷·경로·타임스탬프는 LOG_CONTRACT가 알아서 결정한다.

02 · 섹션 소유권

충돌 없는 공유 파일

각 AI는 자기 섹션에만 쓴다. 동시에 여러 AI가 같은 파일을 열어도 덮어쓰기나 병합 충돌이 발생하지 않는다.

03 · 단일 진실

볼트 검색 하나로 전부

하루 끝에 파일 하나에 모든 AI 활동이 시간순으로 쌓인다. 키워드로 날짜를 가로질러 검색할 수 있다.

04 · 두 가지 일지 유형

daily-log와 work-log 분리

개인 통합 일지(daily-log)와 업무 일지(work-log)를 분리해 같은 규약으로 운영할 수 있다. 경로와 섹션 이름만 다르게 설정하면 된다. 이 패키지는 패턴을 제공한다 — 경로와 섹션 이름은 본인 환경에 맞게 채운다.
